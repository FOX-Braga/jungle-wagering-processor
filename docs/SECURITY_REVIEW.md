# Revisão final de segurança

A primeira consulta de `bun audit` identificou CVE-2025-69873 no Ajv direto e na versão 8.13.0 transitiva do migrator. A versão direta 8.20.0 fica nas dependências de desenvolvimento, pois atende aos testes de OpenAPI. Um override restrito a `@rushstack/node-core-library` resolve o Ajv transitivo em 8.20.0. A série 6 usada pelo ESLint permaneceu em 6.15.0. A instalação congelada passou e a nova auditoria retornou **zero avisos em 307 pacotes**. [Aviso de segurança](https://github.com/advisories/GHSA-2g4f-4pwh-qvx6) · [Manifesto](../package.json)

| Controle   | Evidência                                                                                                                                                                                                                                                                           |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Segredos   | `.env` ignorado pelo Git e pelo contexto Docker. Os arquivos versionados de exemplo usam credenciais de desenvolvimento. A busca por padrões de chave privada e tokens retornou zero correspondências no workspace versionável.                                                     |
| HTTP       | DTO estrito, limite de corpo e de operações em voo, respostas sanitizadas e Swagger conforme ambiente. Os health checks são públicos. [Contrato](API_CONTRACT.md)                                                                                                                   |
| PostgreSQL | TLS exigido no perfil implantável. Testes de privilégios com logins temporários validam a segregação entre runtime, auditoria e dono das migrations. As constraints e os triggers protegem o ledger contra escrita indevida. [Grants](../scripts/bootstrap/database-privileges.sql) |
| SQS        | URLs e perfis validados. Ambiente implantável exige HTTPS e identidade gerenciada ou credenciais apropriadas. O setup protege o redrive e mantém SSE ou KMS conforme o perfil. [Mensageria](MESSAGING_ARCHITECTURE.md)                                                              |
| Logs       | Campos permitidos por lista e escrita estruturada. Testes inspecionam IDs, correlação, isolamento de contexto e ausência de payloads completos, segredos e stacks na saída. [Testes](../test/observability/operations.test.ts)                                                      |

A API de avaliação opera em loopback ou rede isolada. A autenticação ativa fica fora do escopo oficial de pontuação e a porta `ProviderIdentityPort` preserva a extensão para um guard OIDC. Antes de exposição pública, o desenho exige identidade externa e autorização por provedor e carteira. Os papéis e controles SQS do serviço AWS são definidos na implantação. A auditoria de dependências e os testes de configuração cobrem o código e o ambiente de avaliação. [Política operacional](SECURITY.md)
